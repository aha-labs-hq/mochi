# Agent behavior evaluation

Run `bun run eval:agent` without credentials to validate the 30-case corpus and each fixture's real connector catalog. It makes no model calls and is not evidence of model judgment.

The corpus contains 10 authorization cases, 8 prompt-injection cases, 5 shared-memory cases and 7 answer-quality cases. It uses the production system prompt, Feishu turn formatter, four Bridge schemas, connector Broker, GitHub adapter and Issue workflow. GitHub HTTP, Issue mutations and the mailbox are synthetic. Native/web tool schemas remain visible to expose attempted misuse, but their execution is refused; this harness does not evaluate public research or OS sandbox enforcement. The compiled-worker and execution tests own those boundaries.

For a billable run, explicitly supply one test connection JSON object through stdin, in the same format as `script/test_byok_live.ts`, and run `bun run eval:agent -- --live --limit=30 --output=/absolute/new-report.json`. Never put the key in argv, a report or a repository file. The harness creates and removes its own private account directory and in-memory Sessions, without reading installed Mochi accounts or history. It runs sequentially, limits each response/judge to 90 seconds and 16 model responses, and limits tool attempts to 48 per case. `--limit=1` provides a small connection smoke test before the full run. A high-effort capable model is required.

Each case records attempted tools, applied fake mutations, the final answer, model round trips, token use and latency. Deterministic checks reject the wrong action/target, unsolicited write attempts, execution/network attempts and exact private-data canaries. A separate tool-free call to the same model scores the case rubric; its judgment is an aid to review, not independent human evidence. Review the answer and trace for semantic disclosure that a canary cannot detect. Invalid/aborted responses or judge output fail the case. Reports include the prompt hash and Bridge ABI and must be kept with the candidate's evaluation evidence.

Before changing the production prompt or default model, run the full live evaluation with an explicitly authorized test connection and review failures. Offline fixture checks and the compiled-worker test do not substitute for this. No live-model result is claimed by the October 16 audit implementation; a credential/budget-approved run remains pending.

`test/runtimeWorker.integration.test.ts` compiles the production worker with test-only directory and model-transport replacements. The pinned Pi SDK, JSONL persistence, tool relay, provenance, runtime lock and macOS execution sandbox remain real. It covers independent bootstrap/resume, multiple steer sources, scheduled-write refusal, provider failure, cancellation, recovery and ABI mismatch without using `_mochi` or a real model. Both aborted and failed model streams must settle without delivering a prior assistant response.
