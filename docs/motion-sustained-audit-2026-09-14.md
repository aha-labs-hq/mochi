# 持续状态与睡眠节奏复核 · 2026-09-14

用户要求持续状态保持动作，仅最后一轮回到静帧，并再次指出睡眠／苏醒与静帧交接不自然。本次从实际视频编排、播放状态机和原生窗口分别复核；前一轮素材验收不替代这次语义验收。

## 已定位的原因

工作和整理原片都在中间活动后收走道具，随后静止到片尾。旧 `continuous` 从零重复整段，因而每轮都会重演退场、静帧和入场；删除播放器额外的停顿不能消除源视频里的这段编排。

睡眠原片在约第 40 帧闭眼后继续静止到第 95 帧。完整倒放会先重复超过两秒的闭眼等待，再开始醒来。原生窗口复现了这个迟钝响应，不能用首尾像素相等宣称节奏已自然。

## 单一播放合同

manifest 升级到 schema 4。`continuous.sequence` 只引用一个 `sustained` 视频，视频拥有进入、内部循环和退出。`cycle.start` 包含、`cycle.end` 不包含；持续状态只重复这段活动，状态结束后完成当前轮并沿原视频向前收尾。退出一旦开始便完成，随后才可重新进入。逐帧显示，不倒放持续动作，不用淡入淡出隐藏循环接缝。

`sourceFrames` 声明原始视频的连续闭区间；编译器保留其原始帧率，不改速度、不合成中间帧。只允许去掉已逐帧确认不含表演的首尾等待，原片时长仍由生成合同拥有。状态静图取自所选区间的最后一帧，根图与目标接缝继续执行原有门限。

睡眠保留源任务 `cgt-20260914164340-pcpms` 的第 8–43 帧，24 fps、36 帧、1.5 秒。除重新使用唯一根图的第零帧外，35 个保留画面与此前对应视频帧 RGBA 逐像素一致；记录在 `artifacts/mochi-motion/2026-09-14-sustained-cycles/source-exposure-proof.json`。没有重画毛毡边缘、眼睑或静态目标。
